# T028 Security review

Reviewer: implementing agent (self-review against REQUIREMENTS.md SEC-01..06, AGENTS.md and the V5.2
contract). This is not an independent penetration test. Date: 2026-10-10.

Scope: backend API (FastAPI), browser client, deployment package (deploy/), local LLM integration,
data-source query service. Status: **Resolved** = fixed and covered by a test; **Accepted** = residual
risk recorded for the user to accept at G4; **Open** = none.

| ID | Area | Finding | Resolution | Status | Evidence |
|---|---|---|---|---|---|
| SR-01 | SEC-01 authentication | Until T028 the API trusted `X-PDM-User`/`X-PDM-Role` headers (D-010, development only). Anyone on the LAN could claim admin. | Local accounts (`users` table, scrypt hashes), HMAC-signed 12 h session cookie, `PDM_AUTH_MODE=local` in the package; `serve.py` refuses any other mode; dev headers are ignored in local mode; unknown modes return 501. | Resolved | `tests/auth/test_auth.py::test_dev_headers_are_ignored_in_local_mode`, `test_unknown_auth_mode_refuses`; deployment log "development headers ignored", "serve.py refuses PDM_AUTH_MODE=dev" |
| SR-02 | Session handling | Cookie theft / forgery. | Cookie is HttpOnly, SameSite=Strict, Secure when `PDM_COOKIE_SECURE=true`; signature compared in constant time; expiry enforced; server refuses to start with a secret under 32 characters; install.ps1 generates a 48-byte random secret and restricts `.env` to SYSTEM and Administrators. | Resolved | `test_token_is_signed_and_expires`, `test_local_mode_refuses_short_secret`, `test_sign_in_sets_httponly_cookie_and_me` |
| SR-03 | CSRF | Cookie auth enables cross-site POSTs. | All POST/PUT/PATCH/DELETE need `X-PDM-CSRF: 1` (a custom header a cross-site form cannot send; no CORS is configured, so cross-origin scripts cannot add it). | Resolved | `test_state_changes_need_csrf_header`; deployment log "state change without X-PDM-CSRF refused" |
| SR-04 | Brute force | Password guessing. | 5 failures lock the account for 5 minutes; unknown users get the same answer as wrong passwords; every attempt is audited (`auth.failed`, `auth.locked`, `auth.login`). Passwords need 10+ characters. | Resolved | `test_wrong_password_locks_after_five`, `test_unknown_user_gets_same_answer` |
| SR-05 | Account lifecycle | Deactivated or demoted users keep a valid cookie. | Every request re-reads the account; deactivation and role changes apply at once. An admin cannot deactivate or demote themselves (no lock-out of the last admin by accident). Console tool `manage_users.py` creates the first admin and resets passwords. | Resolved | `test_deactivation_ends_existing_session`, `test_roles_apply_and_admin_cannot_demote_self`; deployment log |
| SR-06 | SEC-03 LLM configuration | Viewers could read the Ollama endpoint and allowed hosts (`GET /api/llm/settings`, `/api/llm/health`). | Reading and changing LLM settings and health is admin-only; the Assistant screen hides the settings panel on 403. Data-source credentials were already server-side references only (`credential_ref`, `test_no_endpoint_returns_credentials`). | Resolved | `tests/llm/test_llm.py::test_settings_need_admin_and_reject_remote_targets`; deployment log "non-admin cannot read LLM settings" |
| SR-07 | SEC-04 inference | Remote/cloud inference destinations. | Endpoint must be loopback or private LAN IP (or an admin-listed LAN host name); `*-cloud` model tags refused; validated server-side on every save and call (T027). Ollama itself should listen on 127.0.0.1 or be firewalled to the server (README). | Resolved (app) / Accepted (Ollama host firewall is an operator step) | T027 tests `tests/llm` (35 passed) |
| SR-08 | Browser hardening | No clickjacking / MIME-sniffing headers. | Middleware adds `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`. | Resolved | `test_built_frontend_is_served_with_spa_fallback` |
| SR-09 | Static file serving | Path traversal through the SPA fallback. | Files are served only when the resolved path is inside the static root; everything else gets index.html; `/api/*` misses return 404. | Resolved | `test_built_frontend_is_served_with_spa_fallback` (`/../../etc/passwd` → index.html) |
| SR-10 | Network exposure | Port reachable beyond the plant LAN. | install.ps1 opens the port only to `LocalSubnet`. Transport is plain HTTP by default. | Accepted: HTTPS needs a certificate from the plant's IT; set `PDM_COOKIE_SECURE=true` behind a TLS reverse proxy. |
| SR-11 | Production databases (SEC-06) | Connecting to a real IoT database before approval. | Non-simulated sources in the data-source file are skipped unless `PDM_PRODUCTION_DATA_APPROVED=true` (default false, never set by the installer). Query service remains read-only, template-only, bounded and server-validated (T010). | Resolved | `test_production_sources_stay_off_until_approved`; deployment log "production source skipped until approval" |
| SR-12 | Official alerting (SEC-06) | Alarms reaching people as official maintenance alerts before approval. | No notification channel exists in the code base (alarms are review records only; grep for SMTP/webhook/notification senders finds none). | Resolved (nothing to enable) |
| SR-13 | Audit (SEC-02) | Account changes and sign-ins not audited. | `user.create`, `user.change`, `auth.*` written to `audit_log`, alongside config, template, registry and LLM-setting changes. | Resolved | `test_wrong_password_locks_after_five` reads the audit log |
| SR-14 | Dependencies | Known-vulnerable packages. | Runtime set pinned in `backend/requirements.lock` (35 packages) and verified to have win_amd64/cp312 wheels. No vulnerability scanner was run (no network database available offline). | Accepted: run `pip-audit` on the build machine before each release. |
| SR-15 | Single-process sessions | Lockout counters live in the database; sign-out deletes the cookie but a copied token stays valid until expiry (stateless token). | Deactivating the account revokes it at once; tokens expire after 12 h. | Accepted |

## Not verified here

- The Windows install itself (`install.ps1`, scheduled task, firewall rule) was **not executed**: this environment is Linux. The same package was unpacked and run in production mode on Linux with PostgreSQL (deployment_log.txt).
- A live Ollama server was not available; LLM behaviour was tested against the bundled fake Ollama (`scripts/fake_ollama.py`), and the platform's operation without Ollama was verified.
