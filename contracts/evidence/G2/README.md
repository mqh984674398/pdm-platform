## 2. 请确认的数据语义 / Data semantics to confirm

批准 G2 即接受以下假设；如需修改，请指出编号。Approving G2 accepts these; to change one, name its number.

- **A1 未完成动作 Incomplete operations.** 控制器在动作未完成时上报固定超时值（模拟为 2000 ms）。如知道真实超时值，可直接配置。The controller reports a fixed timeout when an operation does not finish (2000 ms in the simulation). A known real timeout can be configured.
- **A2 工况来源 Regime source.** 由巡航速度和执行器动作间隔判断；若真实系统有配方或程序号信号，应优先使用。参考期由人确认，须覆盖所有常用配方。From cruise speeds and the operation interval; a real recipe or program-number signal, if present, should take precedence. A person confirms the reference period, which must cover every routine recipe.
- **A3 停机与故障 Stopped and fault.** 只根据设备状态或报警信号判断；无数据时段显示“未知”，不推测为停机。Derived only from a status or alarm signal; periods without data are UNKNOWN, never guessed as stopped.
- **A4 维护流程 Workflow rules.** 检查不启动流程；关闭复核需要工程师并填写结论；新维护事件取代未结束的流程；T018 前稳定期与验证由人推进；流程不发出报警。Inspection starts no workflow; closing a review needs an engineer and a comment; a new event supersedes the open workflow; stabilization and validation are moved by people until T018; the workflow sends no alerts.
- **A5 质量阈值 Quality thresholds** (仅用模拟数据调校 / tuned on simulated data only): 缺失 > 2 %，间隔离散 > 5 %，停顿 > 常规 4 倍（事件信号 6 倍，至少 1 小时）为缺口，水平变化 20 倍为单位可疑 / missing > 2 %, interval spread > 5 %, a pause > 4× the usual (6× for event signals, ≥ 1 h) is a gap, a 20× level change is unit-suspect.

## 3. 已知限制 / Known limitations

- 真实 IoT 数据库：需要只读访问或几天的样例导出，用于核实映射和 A1–A3。Real IoT database: read-only access or a few days of sample export is needed to verify the mapping and A1–A3.
- 工况：比已知配方慢不到 30 % 且动作间隔相同的新配方会被归入已知工况（采样可能错过巡航段）。Regimes: a new recipe less than 30 % slower than a known one with the same operation interval would be matched to the known regime (sampling can miss the cruise phase).
- 维护事件只有时间点，没有持续时间。Maintenance events have a time but no duration.
- 代码尚未推送到 GitHub；完整历史在项目文件 `repo-bundle/pdm.bundle`。The code is not on GitHub yet; full history is in the project files at `repo-bundle/pdm.bundle`.
