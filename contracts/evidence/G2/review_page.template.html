工况解释

Operating-regime interpretation

没有配方信号，工况由可观测量判断：每个运行窗口的巡航速度和执行器动作间隔。转矩和动作时间不参与判断，否则劣化会被当成“新工况”而被掩盖。

There is no recipe signal, so regimes come from observables: each running window's cruise speed and the interval between actuator operations. Torque and durations never decide the regime; otherwise degradation would be hidden as a "new regime".

部件生命周期与维护流程

Component lifecycle and maintenance workflow

只有“更换”会开始新的生命周期：旧生命周期退役但保留全部历史。润滑、调整、局部维修、检查都不重置老化计数。S12 的更换结果与模拟器记录完全一致。

Only a replacement starts a new lifecycle: the old one is retired and keeps its full history. Lubrication, adjustment, partial repair and inspection never reset aging. The S12 replacement result equals the simulator's record exactly.

维护后流程（每次维护事件一个流程，检查除外）

Post-maintenance workflow (one per maintenance event, except inspection)

MAINTENANCE_EVENT→STABILIZATION→POST_MAINTENANCE_VALIDATION→NORMAL_MONITORING或orREVIEW_REQUIRED

其他任何转换都被拒绝且不留记录；每次转换都写入审计日志。关闭“需复核”需要工程师并填写复核结论。T018 之前，稳定期和验证步骤由人推进。该流程只记录状态，不发出任何报警。

Any other move is refused and leaves no record; every transition is written to the audit log. Closing REVIEW_REQUIRED needs an engineer and a review comment. Until T018, the stabilization and validation steps are moved by people. The workflow only tracks state and sends no alerts.

请确认的数据语义

Data semantics to confirm

批准 G2 即接受以下假设；如需修改，请指出编号。

Approving G2 accepts these assumptions; to change one, name its number.

  1. 未完成动作的表示How an incomplete operation is reported控制器在动作未完成时上报固定的超时值（模拟为 2000 ms）。已知超时值时请提供，系统可直接配置。The controller reports a fixed timeout value when an operation does not finish (2000 ms in the simulation). If you know the real timeout, it can be configured directly.
  2. 工况来源Where regimes come from由速度和动作间隔判断。若真实系统有配方或程序号信号，应优先使用。参考期需由人确认，并覆盖所有常用配方。From speeds and operation interval. If the real system has a recipe or program-number signal, it should take precedence. A person confirms the reference period, which must cover every routine recipe.
  3. 停机与故障状态Stopped and fault states需要设备状态或报警信号才判断；没有数据的时段显示为“未知”，不推测为停机。Derived only from a machine status or alarm signal; periods without data show UNKNOWN and are never guessed as stopped.
  4. 维护流程规则Workflow rules检查不启动流程；关闭复核需要工程师；新的维护事件取代该部件未结束的流程。Inspection starts no workflow; closing a review needs an engineer; a new maintenance event supersedes the component's open workflow.
  5. 质量阈值（仅用模拟数据调校）Quality thresholds (tuned on simulated data only)缺失超过 2%，间隔离散超过 5%，停顿超过常规 4 倍（事件信号 6 倍，至少 1 小时）为缺口，水平变化 20 倍为单位可疑。Missing above 2 %, interval spread above 5 %, a pause over 4× the usual one (6× for event signals, at least 1 h) is a gap, a 20× level change is unit-suspect.

仍缺：真实 IoT 数据库的只读访问或样例导出（几天的数据即可），用于核实信号映射和上述假设。
