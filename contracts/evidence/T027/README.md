# T027 evidence: Ollama-only LLM, local RAG and feedback

No real model was run. Every test talks to the deterministic fake Ollama (`backend/app/simulation/fake_ollama.py`; served for E2E by `backend/scripts/fake_ollama.py`).

- AC1, remote targets refused (`app/llm/endpoint.py`): endpoints must be loopback, private LAN IPs, `localhost`, or admin-allowlisted LAN host names. Public IPs, other names, link-local addresses, credentials in the URL, paths and non-HTTP schemes are refused. Models are refused when cloud-routed (`*-cloud`, `:cloud`), when they name a registry host, when not on the allowlist, or when not installed. Settings changes need an admin, are re-validated and audited. The client validates again before any request and ignores proxy environment variables (`trust_env=False`).
- AC2, gateway (`app/llm/client.py`): health, version and models; chat with JSON-schema output; NDJSON streaming with cancellation (`threading.Event`, `POST /api/llm/ask/{id}/cancel`, or client disconnect); typed timeout and unavailable errors. Answers must validate as `AssistantAnswer` (else 502 `llm_bad_answer`). A guard removes sentences about failure probabilities, remaining useful life, safety changes, overriding rules or alarms, publishing models, or PLC/servo control, and records a note for each.
- AC3, RAG (`app/llm/rag.py`): engineers add documents; an admin approves, which chunks and embeds them through the local Ollama. Retrieval returns only approved chunks the caller's role may read. Citations not among the retrieved chunks are dropped. Retrieved text is fenced as untrusted; a test shows an injected "disable the safety rule" note being retrieved and the instruction removed from the answer.
- AC4, Ollama down: the fleet overview, alarm evaluation and health reports work; the assistant answers 503 `llm_unavailable`; health reports `reachable: false`. The assistant is off by default (`LlmConfig.enabled = False`).
- AC5, live tests: `tests/llm/test_live.py` is skipped unless `PDM_OLLAMA_LIVE_URL` is set. **It was not run**: this build environment has no Ollama. The opt-in live log still has to be produced on the target machine.
- Feedback (FB-01, `app/feedback/service.py`): maintenance and above can submit feedback on alarms, decisions, maintenance records or assistant answers. It goes to PENDING_REVIEW, is reviewed by an engineer, is audited, and never touches baselines (a test checks the reference count is unchanged).
- UI: `/assistant` covers Ollama settings and health, asking with streaming and cancel, citations, guard notes, and the rules' health badge, rating an answer, and documents (add and approve). Alarms gained "Confirmed / False alarm" feedback buttons.
- Tests: `pytest tests/llm` (35 passed, 1 skipped live); E2E `tests/e2e/assistant.spec.ts`.
- CI (`ci_local.log`): backend 520 passed and 1 skipped on Python 3.11 and 3.12, schema drift OK, frontend 42 unit and 15 E2E passed.
